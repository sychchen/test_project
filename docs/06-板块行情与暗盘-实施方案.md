## Part A. 板块行情（需求 #19）

### A1. 需求原文

> 参考同花顺或者常用证券软件，做不同"板块"的行情内容。至少需要有以下内容：
> 1、基础信息需要：成分股数量、创建日期、总市值、流通值、人气排名等最新指标，还需要有板块概念解读
> 2、板块成分股，以及成分股中高相关的成分股是哪些，龙头股是哪些（可以打标签）
> 3、日行情看能获取多次时间的历史数据，尽可能把更多的历史数据落到表中，分时行情保留最近30个交易日的就行

### A3. 关键设计决策（**核心思路：能用本地算的一律本地算**）

本地已有 **`stock_basic`（4602 只，含 `industry` 申万行业、`concepts` 概念列、`total_mv`/`circ_mv`/`pe_ttm`/`pb`）** 与 **`stock_daily_quote`（246 个交易日 × 5216 只）**，因此：

| 需求项 | 实现路径 | 口径定义 |
|---|---|---|
| 成分股数量 | **本地聚合**：`concepts`/`industry` 反推 distinct 成分股 | 当前活跃成分股数（含停牌） |
| 总市值 / 流通值 | **本地聚合**：`SUM(total_mv)` / `SUM(circ_mv)` | 最新快照（`stock_basic`） |
| 板块创建日期 | ⚠️ **外源普遍不公开** → 用「成分股最早上市日 `MIN(list_date)`」或「板块内最早行情日」作为**代理口径**，字段名标 `list_proxy_date` 并在 UI 注明"代理口径" | 需决策（见 A5） |
| 人气排名 | **外部采集**（同花顺热榜，每日盘后 1 次）→ 板块人气 = 成分股人气排名中位数/前 10 均值 | 需决策（见 A5） |
| 板块日线·成分覆盖门槛 | **2026-09-16 加**：当日有效成分股数 < max(3, 20%×成分股数) 不出行。原实现按日期全集出行，实测 470 个板块-日仅由 **1 只**成分股构成（电子器件早期 58 天更是只有 1 只股票，指数退化为个股走势）。加门槛后剔除 905 个板块-日，全表 49,603 行 / 1,032 交易日 | ✅ 2026-09-16 |
| 板块日线·均线口径 | **2026-09-16 修**：`ma5/ma10/ma20` 原以**实际切片长度**作分母，序列初段用「短窗均值」冒充（第 2 根即给出 MA20）；改为 `i >= w-1` 才有值，与 `stock_daily_quote` / `stock_index_daily`「满窗才有值」口径一致（NULL 数 = 49 板块 × 4/9/19 = 196/441/931） | ✅ 2026-09-16 |
| 板块概念解读 | **本地生成（已落地）**：`board_synth.BOARD_DESC` 49 条行业知识库（行业范围 + 关键驱动）+ 实时统计（成分股数/市值/龙头/近20日涨跌幅）两段式拼装 | ✅ 2026-09-15 |

| 高相关成分股 | **本地计算**：个股收盘价与板块合成指数 **60 日收益率相关系数**，取相关系数 ≥ 0.7 或 TOP20% | 可复现、无需外部数据 |
| 龙头股（打标签） | **本地打分**：`0.4×流通市值分位 + 0.3×近 20 日涨幅分位 + 0.3×近 20 日成交额占比分位`，TOP3 打「龙头」标签 | 透明可解释 |

### A5. 需确认的 3 个决策点

1. **板块体系选谁**：`本地 concepts/industry`（4602 只全覆盖、已有口径）／`东财 BK 板块 496 个`（行业+概念最全，列表接口可用）／`新浪行业板块`（约 100 个行业）。**建议：以东财 BK 板块为主表，用板块名称匹配本地 `concepts`/`industry` 生成成分股（因为 BK 成分股接口被封），新浪行业做交叉校验。**
2. **板块日线合成口径**：分时/日线用 **流通市值加权**（更接近同花顺/东财板块指数）还是 **等权**（更能反映普涨普跌）？**建议流通市值加权**，同时落一列等权涨跌幅便于对照。
3. **日线历史长度**：当前 246 个交易日可直接合成；若要 **3~4 年**，需先为全部成分股补采长历史（腾讯 `fqkline` 单票可拉 1023 根 ≈ 4 年，**每票 1 次请求**，约 5200 次、预计数分钟），之后再合成。**建议先落 246 天（零增量采集），长历史作为第二步。**

## Part B. 暗盘数据（需求 #20）

### B1. 需求原文

> 我想做暗盘数据逻辑，你建议怎么进行实现？实现方案的设计原理是什么，确认好后你按具体的实现方案进行执行开发

### B2. 先澄清一个前提：A 股**没有**「暗盘」

「暗盘」在证券语境里通常有两种含义，必须二选一（或都做），否则开发方向会完全跑偏：

| 口径 | 含义 | 与本项目（A 股池、沪深主板+创业板）的关系 |
|---|---|---|
| **① 港股新股暗盘** | 新股正式上市**前一交易日 16:15–18:30**，由券商（辉立/耀才/富途）内部撮合的**场外交易**，不通过港交所。是港股打新的核心参考 | 需要**港股**数据源（本项目当前只有 A 股），且需新股上市日历 → 属于**新建数据域**，工作量最大 |
| **② A 股「盘后交易」/大户与机构私下成交** | 即 **大宗交易**（盘后协议转让，折价/溢价成交，不冲击盘中价格）与 **龙虎榜席位**（游资/机构专用席位）。俗称「暗盘资金」「场外成交」 | **完全落在本项目域内**，且数据源已验证可用（见 B3） |

> **我的判断**：以本项目现有股票池（沪深主板+创业板，无港股、无新股日历）来看，需求 #20 的合理落点是 **口径 ②**——即"盘后/场外资金（大宗交易 + 龙虎榜）"数据域，用于补充**「主力行为的暗线信号」**：盘中看不到、盘后才披露，但往往领先于价格。

### B4. 设计原理（为什么要做、怎么用）

**核心原理：信息不对称的时间差。**
- **盘中**的成交是"公开暗牌"——所有人都能看到价格与成交量，但看不到**是谁在买、以什么价格协议成交**。
- **大宗交易**在盘后披露：折价率（`PREMIUM_RATIO`）是**唯一可量化的"机构意愿"指标**。持续**溢价成交**（买方愿意高于市价接货）通常意味着机构看好；持续**大幅折价**（通常 8%~10%）则多为解禁股东减持出货。**8 折以上的大幅折价 + 连续多日 = 强减持信号。**
- **龙虎榜**在盘后披露席位：`机构专用` 席位净买入 → 机构建仓；知名游资营业部 → 情绪驱动；`DEAL_AMOUNT_RATIO`（成交占比）越高，说明该股当日成交被少数席位主导 → 筹码集中度突变。
- **两者共同构成"盘后暗线"**：盘中选股（现有 7 策略）看的是**价量形态**；暗盘数据补的是**资金身份与协议价格**，可作为**选股结果的二次过滤/加分项**，也可独立成策略（如"大宗溢价 + 龙虎榜机构净买"）。
