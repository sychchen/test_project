# 选股系统 — 需求分析文档

> 版本：v1.4 ｜ 日期：2026-09-15 ｜ 状态：已确认
>
> v1.4 变更：补充日频衍生指标（连涨天数/连涨涨幅/量比/换手率）、表格自定义排序与指数成分筛选、
> 筛选框兜底查询、K 线指标可视化增强、个股资金流向日频数据补全；数据源口径更新为
> 「腾讯 fqkline 主源 + 新浪兜底」，估值统一腾讯 TTM 口径。

## 1. 项目背景与目标

构建一套**基于真实 A 股市场数据**的量化选股系统，实现「数据采集 → 数据存储 → 策略选股 → 结果展示」全链路闭环，帮助用户按预设策略从全市场 5000+ 只股票中筛选出符合买入条件的候选标的。

### 业务目标

| 目标 | 说明 |
|---|---|
| 数据真实可靠 | 通过公开行情接口（新浪财经）获取真实市场数据，非模拟数据 |
| 策略可扩展 | 策略引擎插件化，新增选股策略只需新增一个策略类 |
| 结果可追溯 | 每次选股结果落库，含执行批次、策略参数、命中明细，可回看历史批次 |
| 使用门槛低 | Web 页面一键执行策略、查看结果、浏览 K 线行情，无需命令行 |

## 2. 用户场景

1. **每日盘后备选股**：用户盘后执行「均线多头」策略，系统基于当日收盘行情筛选出多头排列的个股列表。
2. **突破信号捕捉**：用户执行「放量突破」策略，筛选近 20 日新高且成交量显著放大的个股。
3. **价值筛选**：用户执行「低估值」策略，基于 PE/PB/总市值等基本面指标筛选低估值标的。
4. **历史回看**：用户按日期/批次查询历史选股结果，复盘策略命中率。
5. **行情浏览**：用户在「K线行情」中搜索个股，查看其板块标签、日K 走势与当日分时。

## 3. 功能需求

### 3.1 数据采集模块（F1）

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1-1 | 获取 A 股全市场股票列表（代码、名称、所属市场） | P0 |
| F1-2 | 获取个股日线历史行情（开高低收、成交量、涨跌幅）；**默认增量采集最近 2 个交易日**，同时**支持采集指定时间段**（start_date ~ end_date）。主源腾讯 `fqkline`（不复权），新浪 `getKLineData` 兜底 | P0 |
| F1-3 | 获取个股基本面快照（PE-TTM、PB、总市值、流通市值），估值统一**腾讯 TTM 口径**；日频快照随 `--valsnap` 拷入日线表前滚积累 | P1 |
| F1-4 | 采集失败容错：单票失败不影响整体批次，记录失败清单 | P0 |
| F1-5 | 采集个股**每日分时数据**（5 分钟 K 线，48 根/日）落库，前滚积累（2026-09-09 起取消"仅保留3日"清理；历史区间由 baostock 按需回填） | P0 |
| F1-6 | 基础信息增加**板块标签**：申万行业（单值）+ 概念板块（多值）+ 指数成分（上证50/沪深300/中证500/科创50/创业板指） | P0 |
| F1-7 | **个股资金流向（日度）**：主力/超大单/大单/中单/小单净额 + 主力净占比，按交易日前滚积累；历史区间（2025-09-09 起）按需补全 | P1 |
| F1-8 | **日频衍生指标**：连涨天数、连涨涨幅、量比、换手率，随日线增量自动计算并落库，支持全表/区间重算 | P0 |
| F1-9 | **板块行情（新浪行业板块）**：板块基础快照（成分股数/总市值/流通值/涨跌家数/领涨股/人气）、成分股映射+相关度+龙头标签、板块日线（成分股流通市值加权合成，先落 246 个交易日）、板块分时（成分股分时合成，保留近 30 个交易日）。口径详见 `06-板块行情与暗盘-实施方案.md`（2026-09-15 已确认） | P1 |
| F1-10 | **暗盘数据（A 股盘后暗线）**：大宗交易逐笔（折溢价率/买卖方）+ 龙虎榜（净买入/机构席位/成交占比），盘后披露、低频采集（≥0.5s 间隔）；派生 `dark_score` 暗盘信号指标（机构吸筹/减持出货/游资活跃）。口径详见 `06-板块行情与暗盘-实施方案.md`（2026-09-15 已确认） | P1 |

### 3.2 选股策略模块（F2）

| 编号 | 策略 | 规则 | 优先级 |
|---|---|---|---|
| F2-1 | 均线多头（MA Bull） | MA5 > MA10 > MA20，且收盘价站上 MA20，近 3 日 MA5 上行（剔除ST） | P0 |
| F2-2 | 放量突破（Volume Breakout） | 收盘价创近 20 日新高，当日成交量 ≥ 20 日均量 × 2，当日涨幅 > 3%（剔除ST） | P0 |
| F2-3 | 低估值（Value） | 0 < PE-TTM < 20，0 < PB < 2，总市值 ≥ 100 亿（剔除ST） | P1 |
| F2-4 | MACD 金叉 | DIF 上穿 DEA，可参数要求零轴上方（剔除ST） | P1 |
| F2-5 | 缩量回调 | MA20 上行趋势中回调 1%~12% 不破 MA20，量比 < 0.7，贴近 MA10（剔除ST） | P1 |
| F2-6 | 连续阳线 | 连续 4 日收阳且逐日走高，累计涨幅 ≤ 15% 防追高（剔除ST） | P1 |
| F2-7 | 策略引擎支持策略注册/参数化，可多策略批量执行 | P0 |

> **硬性约束**：全部策略一律不选 ST 股（名称含 "ST" 即剔除），代码层与结果层双重验证。

## 5. 非功能需求

- **性能**：全市场日线增量更新 ≤ 2 分钟（腾讯主源 16 线程实测约 2~3 分钟）；全市场分时采集 ≤ 2 分钟（实测约 83 秒）；单策略冷启动选股 ≤ 150 秒、热缓存约 3.5 秒；7 策略全量 `run_pick.py --all` 约 106 秒（共享数据加载）
- **可靠性**：采集断点可重跑（按交易日/分钟 bar 幂等覆盖）；资金流历史回填支持断点续跑（按缺口逐股比对）
- **环境**：Windows 本地运行，Python 3.13；数据库 MySQL 5.5.60 @ 172.16.3.16:30306/test_project
- **部署**：仅本地部署，一键启动脚本（启动 API + 打开页面），服务地址 http://127.0.0.1:8600
- **兼容性**：MySQL 5.5 无窗口函数/无派生表索引，复杂口径一律改为「单独查询 + Python 侧合并」

## 6. 约束与假设

- 免费公开行情接口存在频控/反爬，采集需并发控制、重试与失败清单
- **各源反爬阈值实测**：腾讯 fqkline WAF 约 5000+ 次/短窗口（110 req/s 触发 501）；新浪约 400 次/窗口（返回 456 挑战页，约 5 分钟恢复）
- **东财 `push2his` 对本机 IP 长期封禁**（`RemoteDisconnected`），且已被明确排除，资金流类历史数据一律不使用该接口
- **东财资金流各域实测结论（2026-09-15）**：`push2his` / `push2.eastmoney.com` 连接被重置（IP 封禁）；`push2delay`（日常链路在用）**仅保留最新一个交易日**（`lmt=0` 也只返回 1 根），无历史；`datacenter-web` 无该接口。→ **资金流历史只能取新浪**
- **新浪同接口双域名限流互相独立**：实测 `vip.stock.finance.sina.com.cn` 返回 456 挑战页时，`money.finance.sina.com.cn` 仍正常 200 → 回填按 `crc32(ts_code) % N` 稳定分片 + 按域名分片并行，整体吞吐翻倍
- 新浪与东财对「主力/超大单」分档阈值不同（同一日同一股主力净额差异 1.5~3 倍，个别日甚至符号相反），**经确认采用混合口径**：最近 5 个交易日（2026-09-08~09-14）保留东财日常采集口径，其余 241 天用新浪补齐，回填一律 `INSERT IGNORE` 只补缺口、不覆盖既有行（不做 `--overwrite`），以满足"不动已有数据"的要求
- 分时数据前滚积累（2026-09-09 起取消"仅保留 3 个交易日"的自动清理）；新浪分钟接口 datalen 上限 1023 根（约 21 个交易日），更早历史由 baostock 按区间一次性回填（`--minbackfill`）
- 新浪股票名称含全角/半角空格（如 `万 科Ａ`），代码/名称检索需做空格不敏感匹配
- 系统仅供研究学习，不构成投资建议
