## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 数据源 | 腾讯 fqkline（日K 主源）+ 新浪财经公开接口（兜底/列表/分时/标签/资金流）+ baostock（历史回填） | 免费、无需 token、真实 A 股数据；东财 push2his 被网络阻断且已弃用；腾讯/新浪双源互为熔断兜底 |
| 数据库 | MySQL @172.16.3.16:30306/test_project | 用户指定 |
| ORM | SQLAlchemy 2.x + PyMySQL | 标准、可移植 |
| 计算 | pandas | 均线/MACD 等指标向量化计算 |
| API | FastAPI + Uvicorn | 轻量、自带 OpenAPI 文档 |
| 前端 | 原生 HTML + ECharts 5.5（本地 lib 引入）+ Fetch API | 零构建、本地即用；K线带十字光标悬浮指标值/滚轮缩放/拖动平移/底部滚动条 |

### 3.2c `stock_money_flow` — 个股资金流向表（日度）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 主键 |
| ts_code | VARCHAR(16) | 股票代码 |
| trade_date | DATE | 交易日 |
| main_net | DECIMAL(20,2) | 主力净流入额（元） |
| super_net | DECIMAL(20,2) | 超大单净流入额 |
| large_net | DECIMAL(20,2) | 大单净流入额 |
| mid_net / small_net | DECIMAL(20,2) | 中/小单净流入额（新浪通道不提供，置 NULL） |
| main_pct | DECIMAL(8,3) | 主力净占比 % |
| etl_insert_time / etl_update_time | TIMESTAMP | ETL 时间 |

唯一键：`uk_code_date(ts_code, trade_date)`。**已完整覆盖 246 个交易日（2025-09-09 ~ 2026-09-14）共 1,272,704 行 / 5218 只**，
逐股行数与 `stock_daily_quote` 区间行数完全一致（缺口 0）。

**口径分层（重要）**：日常链路用**东财 `push2delay` clist 批量快照**（仅能取当天，`mid_net`/`small_net` 有值）；
2025-09-09 起的更早历史由**新浪 `ssl_qsfx_zjlrqs`** 回填补齐（`mid_net`/`small_net` 置 NULL）。
两口径对「主力/超大单」分档不同，同一日主力净额差异 1.5~3 倍（个别日符号相反）。
跨 2026-09-08~09-14 与更早日期的资金流对比需注意断层；仅按交易日切片（不对齐历史）使用时不受影响。

## 4. 采集流程设计

### 4.1 日线行情（增量 + 区间双模式）

```
sync_daily_quotes(days=2, start_date=None, end_date=None)
        │
        ├─ 增量模式（默认）：datalen = days + 30（均线预热）
        │    入库前裁剪至最近 days 个交易日
        ├─ 区间模式：datalen ≈ (区间跨度 + 30) / 1.4 + 30（上限 1023）
        │    入库前裁剪至 [start_date, end_date]
        ▼
8 线程并发拉取新浪日K（thread-local Session，3 次重试，trust_env=False 直连）
        ▼
pandas 计算 pre_close/pct_chg/ma5/ma10/ma20/vol_ma20（nan 逐值清洗为 NULL）
        ▼
ON DUPLICATE KEY UPDATE 幂等入库（uk: ts_code+trade_date，etl_update_time=NOW()）
```

- **均线预热**：datalen 多取 30 根用于 ma20 计算，入库前再按目标范围裁剪，保证增量模式下均线值与全量一致
- **实测性能**：全市场 5215 只增量 2 日约 74 秒

### 4.2 分时行情（v1.2 新增）

```
sync_minute_quotes(scale=5, days=1)：datalen = 48 × days
        │
        ▼
8 线程并发拉取新浪分钟K（scale=5，48 根/日）
        ▼
vol 股→手换算 → UPSERT（uk: ts_code+scale+bar_time）
```

- **实测性能**：全市场 5215 只约 83 秒，250,320 行（48 根 × 5215），零失败
- 2026-09-09 起取消"清理 3 个自然日前旧数据（KEEP_DAYS=3）"，分时数据前滚积累

### 4.2b 历史分时回填（2026-09-09 新增）

```
backfill_minutes(start_date, end_date, scale=5)（--minbackfill，不进 --all）
        │
        ▼
baostock query_history_k_data_plus(frequency=5) 单连接顺序查询全市场
        ▼
vol 股→手换算 → UPSERT（同 minute_collector 口径，幂等可重跑）
```

- **背景**：新浪分钟接口 datalen 上限 1023 根（5分钟线约 21 个交易日），更早历史无法回溯；baostock 分钟线按日期区间可查（实测茅台 2026-06-29~07-27 返回 1008 根 = 21 交易日 × 48 根/日，齐全）
- **速率**：baostock 单连接 TCP（非线程安全），全市场约 2-4 小时；首次回填 2026-06-27~2026-07-27 完成（5201/5216 只，523 万行，0 失败）
- **断点续跑**：`skip_filled=True` 跳过区间内已有数据的 ts_code（单票单事务全有或全无，有行即完成）；会话重启会杀后台任务，长跑任务重跑时务必带此参数

### 4.3 板块标签（v1.2 新增）

```
Market_Center.getHQNodes（http 协议）解析节点树
        │
        ├─ 申万行业 31 个节点 → industry（单值）
        ├─ 概念板块 214 个节点 → concepts（逗号分隔，≤20 个）
        └─ "指数成分"子树按白名单递归解析 → index_tags
             （上证50/沪深300/中证500/中证1000/科创50/创业板指）
        ▼
逐节点 getHQNodeData 分页拉成分股 → symbol → 标签映射
        ▼
批量 UPDATE stock_basic（列不存在时幂等 ALTER 添加）
```

- **实测覆盖**：行业 5215/5215（100%）、概念 3031（58%）、指数 785（15%，白名单口径）

### 4.3.1 概念板块补强：东财概念（v1.4 新增，`em_concept_collector.py`）

新浪概念体系陈旧、热点覆盖差（实证：中际旭创仅"黄河三角"、超声电子无"PCB"），
故以东方财富 push2delay 延时通道补强热点概念（PCB / CPO概念 / 液冷服务器 / 算力概念等）：

```
push2delay.eastmoney.com/api/qt/clist/get
        │
        ├─ 板块列表 fs=m:90+t:3+f:!50 → 约 500 个概念板块（分页，单页上限100）
        └─ 逐板块成分 fs=b:BKxxxx → 6位代码 → 概念映射
        ▼
与新浪概念合并去重（东财概念在前，每股上限 24 个）→ UPDATE stock_basic.concepts
```

- 单线程低并发（东财通道并发封 IP，实测约 5-8 分钟全量）
- 执行顺序：必须在 `--tags`（新浪）之后，否则新浪全量覆盖会冲掉东财概念；`--all` 已内置该顺序
- 触发：`python run_collect.py --emconcepts` 或采集页「采集东财概念」按钮（`POST /api/collect/emconcepts`）

### 4.4 日频衍生指标（v1.4 新增，`app/collector/indicator_collector.py`）

统一管理 `stock_daily_quote` 上的四个衍生指标列，口径见 3.2：

| 指标 | 口径 | 依赖 |
|---|---|---|
| cont_days | 连续上涨 = +n，连续下跌 = -n，平盘 = 0；方向反转即从 ±1 重新计数 | pct_chg |
| cont_pct | 与 cont_days 同段的累计涨跌幅，(∏(1+pct/100) − 1)×100；平盘为 NULL | pct_chg + cont_days |
| vol_ratio | 当日成交量 / 前 5 个交易日均量（前 5 日为 t−1..t−5） | vol |
| turnover_rate | vol(手)×close×10000 / circ_mv(元) | vol / close / circ_mv |

两条写入路径：

1. **增量（日常盘后）**：`--quotes` 时由 `quote_collector` 顺带计算 cont_days / cont_pct /
   vol_ratio（三者自足于 K 线，零额外请求）；turnover_rate 依赖 `circ_mv`，由 `--valsnap`
   （`snapshot_valuation`）在估值落库后用**一条 SQL UPDATE** 计算。
2. **全量/区间重算**：`python -m app.collector.indicator_collector [--days N]`。MySQL 5.5 无
   窗口函数，故按 `ts_code` 分组在 Python 侧滚动计算，写临时表后 `UPDATE JOIN` 一次性刷回。
   实测全表 127 万行：读取 34s + 计算 36s + 临时表写入 162s + UPDATE JOIN ≈ 315s。
   `--days N` 模式内部会多读 30 个交易日作预热窗，保证连涨计数与量比在窗口边界处仍正确。

编排：`run_collect.py --indicators`（`--all` 时自动以 `--days 3` 执行），**必须排在
`--quotes` + `--valsnap` 之后**。

### 4.5 个股资金流向历史回填（v1.4 新增）

**东财各域实测结论（2026-09-15）**：

| 域名 | 结果 |
|---|---|
| `push2his.eastmoney.com` | `RemoteDisconnected`（IP 长期封禁，**已被需求明确排除**） |
| `push2.eastmoney.com` | 同上，连接被重置 |
| `push2delay.eastmoney.com` | ✅ 可用，但 `fflow/daykline` 的 `lmt=0/400` **均只返回最新 1 根** → 无历史（日常链路靠它的 clist 批量快照取当天） |
| `datacenter-web.eastmoney.com` | 可达但无该接口（`请求url格式异常`） |

→ **资金流历史只能取新浪**，用 **`MoneyFlow.ssl_qsfx_zjlrqs`**（`num=400` 单次可回溯至 2025-01-21，覆盖目标区间）：

```
backfill_money_flow.py            # 单轮：逐股拉取 → 解析 → INSERT IGNORE 入库
        └── backfill_money_flow_loop.py   # 驱动器：反复跑单轮直到无缺口
```

| 机制 | 说明 |
|---|---|
| 口径映射 | `main_net = netamount`、`super_net = r0_net`、`large_net = netamount − r0_net`、`main_pct = ratioamount×100`、中/小单置 NULL |
| 只补缺口 | 默认 `INSERT IGNORE`（`--overwrite` 才 UPSERT），保住库内既有东财口径行，**按确认不走覆盖** |
| **双域名分片** | `--host {vip,money}` + `--shard I/N`：新浪同接口在 `vip.stock.finance` 与 `money.finance` 两域名下**限流互相独立**（实测一个 456 时另一个仍 200）；按 `crc32(ts_code) % N` **稳定分片**（与缺口列表组成无关，各片严格互斥），两实例并行整体吞吐翻倍 |
| 全局节奏 | `mp.Manager()` 共享 `next_ts`，多进程合计 QPS ≈ 1/interval（而非每进程 1/interval） |
| 请求预算 | `used` 按**真实发出的 HTTP 请求**计数（而非任务数），预算耗尽即本轮停止、可续跑 |
| 熔断 | 识别 456 挑战页/非 JSON → 立即冷却（不浪费重试额度）；冷却结束后速率复位到基准值 |
| 断点续跑 | `pending_stocks()` 逐股比对日线行数与资金流行数，天然支持反复重跑 |

**参考吞吐与冷却调参（实测）**：

| 域名 | 限流后恢复 | 可用窗口 | 建议 `--cooldown` | 实测速率 |
|---|---|---|---|---|
| `money.finance.sina.com.cn` | 约 **60s** | 约 60s | **70** | 442 只 / 94s ≈ **4.7 req/s（约 280 只/分钟）** |
| `vip.stock.finance.sina.com.cn` | 约 **204s** | 约 120s | 200 | 约 **1 req/s（约 60 只/分钟）** |

- 两个域名额度独立 → 可一边跑 money、一边跑 vip；但 **money 快 4~5 倍**，剩余量不大时直接用 money 更快。
- **冷却必须按域名设置**：早期两片都沿用 `--cooldown 200`，对 money 而言每轮白等约 140s，白白损失 2~3 倍吞吐。
- 失败即熔断（不重试）+ 冷却后速率复位，是达成上述速率的前提。
- 最终结果：`stock_money_flow` **1,272,704 行 / 246 个交易日 / 5218 只**，逐股行数与 `stock_daily_quote` 完全一致（缺口 0）。

**口径差异（重要）**：新浪与东财对「主力/超大单」分档阈值不同，同一日同一股主力净额差异
1.5~3 倍，个别交易日甚至符号相反（如 `000001.SZ 2026-09-08`：新浪 +4,319 万 vs 东财 −6,130 万）。
因此**最近 5 个交易日保留东财口径、更早 241 天为新浪口径**，跨这 5 天做时间序列对比时需注意口径断层。
备选统一方案（未采用，留档）：新浪 `MoneyFlow.ssl_bkzj_ssggzj` 批量实时快照与历史接口**口径逐位一致**
（实测 `sh600172 2026-09-14` 三项字段完全相同），可作为日常链路切新浪、实现全表统一口径的路径。

## 5. 策略引擎设计

```python
class BaseStrategy(ABC):
    code: str            # 策略代码，如 "MA_BULL"
    name: str            # 中文名称
    default_params: dict # 默认参数
    def select(self, df_quotes, df_basic, params) -> list[PickResult]
```

- 策略通过 `STRATEGY_REGISTRY` 注册，`/api/strategies` 列出全部可用策略
- 输入：库内行情（pandas DataFrame）+ 基本面快照
- 输出：命中明细（含 score 与 hit_reason），整体作为一个 batch 落库

### 策略规则（与需求 F2 对齐，v1.5 复查后）

| 策略 code | 规则伪代码 | score 定义 |
|---|---|---|
| MA_BULL | close>ma20 且 ma5>ma10>ma20 且 ma5 连续 3 日上行 且 **ma20 近 5 日上行** | (ma5-ma20)/ma20×100 |
| VOLUME_BREAKOUT | close=近20日最高收盘 且 vol≥2×**前20日均量(不含当日)** 且 pct_chg>3 且 **非涨停** | vol/前20日均量 |
| VALUE | 0<pe_ttm<20 且 0<pb<2 且 total_mv≥1e10 | 20−pe_ttm |
| MACD_GOLDEN | 昨 DIF≤DEA 且 今 DIF>DEA（EMA12/26/9），可参数要求零轴上方；**样本≥60 根** | DIF−DEA |
| PULLBACK | ma20 上行 且 **ma10>ma20** 且 前3日高点回调1%~12%不破ma20 且 vol<0.7×**前20日均量** 且 贴近ma10(±3%) | (1−vol/前20日均量)×100 |
| CONSEC_YANG | 连续4日 close>open 且收盘逐日抬升 且 累计涨幅≤15% 且 **量能≤前20日均量3倍** | 累计涨幅% |
| WEEKLY_MAINLINE | 主线/轮动双池 + 指数环境 + 资金流硬过滤（见 §5C） | 见策略源码 |

### 5A. 策略市面常用性复查与修正（2026-09-15，需求 #18）

**市面常用性结论**：7 个策略中 6 个是市面标准策略（同花顺/东财公式可直接表达），1 个为自研主题策略。

| 策略 | 市面对应 | 常用性 |
|---|---|---|
| MA_BULL | 均线多头排列 `MA5>MA10>MA20` | ✅ 极常用 |
| MACD_GOLDEN | `CROSS(DIF,DEA)` MACD 金叉 | ✅ 极常用 |
| VOLUME_BREAKOUT | 放量突破前高（量价齐升） | ✅ 常用 |
| PULLBACK | 回踩均线低吸（多头排列+缩量回踩10日线） | ✅ 常用 |
| CONSEC_YANG | 红三兵/连续阳线 | ✅ 常用 |
| VALUE | 低 PE/PB 价值筛选 | ✅ 常用 |
| WEEKLY_MAINLINE | 主线分歧低吸 + 轮动套利（自研） | ⚠️ 非通用（主题策略） |

**实测量化后执行的修正**（命中数以 2026-09-14 基准日、246 个交易日数据为准）：

| # | 问题 | 实测证据 | 修正 | 命中数 |
|---|---|---|---|---|
| 1 | VOLUME_BREAKOUT 未排除涨停，命中标的次日无法按收盘价买入 | 61 只命中中 **24 只(39%)** 涨幅≥9.5%（含 10%/20% 涨停） | 新增 `exclude_limit_up`（按板块判 10%/20% 涨停，留 0.3% 余量） | 61 → 45 |
| 2 | PULLBACK 参数 `pullback_days` 未生效（实现取 `tail(n+3)`=6 日） | 参数语义 = 3 日，实现 = 6 日 | 改为「前 n 日(不含今日)最高价 → 今日回落幅度」 | — |
| 3 | 量能基线 `vol_ma20` 含当日，且措辞"量比"与系统「量比」列同页不同义 | 名义 2 倍实际 ≈2.02 倍（+0.9%，方向更严） | 三策均改用「前 20 日均量(不含当日)」，措辞改「放量倍数/缩量比/量能倍数」 | — |
| 4 | MACD_GOLDEN guard 仅 `len≥10`，EMA(12/26/9) 未收敛 | 4590 只中仅 15 只不足 60 根、**且无一命中** → 当前无影响，但次新股会产出伪金叉 | `min_bars` 默认 60 | 80 → 80（零变化） |
| 5 | MA_BULL 缺 MA20 中期趋势确认（市面标准含 `MA20>REF(MA20,1)`） | 436 只命中中 **59 只(14%)** MA20 近 5 日并未上行 | 新增 `ma20_rising_days=5` | 436 → 377 |
| 6 | PULLBACK 只要求 MA20 上行+站上 MA20，未确认多头排列 | 经典回踩低吸为「多头排列+回踩10日线」 | 新增 `require_bull_ma`（MA10>MA20） | 175 → 181 |
| 7 | WEEKLY_MAINLINE `_flow_depth()` 用全表计数，未按 t0 截断（未来函数隐患） | 当前被 `flow_map=None` 掩盖，无实际偏差 | 改 `_flow_depth(t0)` 按 `trade_date<=t0` 计数 | 0（指数死叉按纪律空仓） |
| 8 | WEEKLY_MAINLINE `min_hist_days=21`，RSI14(Wilder) 未收敛 | — | 提到 60（≈3 倍周期） | — |

**待决策（语义级变更，未擅自修改）**：

1. **价格复权口径（影响最大）**：`stock_daily_quote` 现为**不复权**价（腾讯 `param=code,day,,,N,` 末段留空）。除权除息日会产生"假跌幅"，污染 MA5/10/20、近 N 日新高的比较基准与连涨天数；市面（同花顺/东财）默认**前复权**。改造方案：单次全量前复权重采（`param=code,day,,,N,qfq`，每票 1 次请求，约 5200 次，与窗口长度无关），口径变化会同步影响 K 线图展示与回测。**→ 2026-09-15 已决策：暂不改，维持不复权口径。**
2. **VALUE 缺质量因子**：332 只命中以银行为主（PE 4 倍/PB 0.32），属典型"低估值陷阱"。市面优化需引入 ROE/股息率等质量因子——当前数据源无该字段，需先补数据。
3. **CONSEC_YANG 可加红三兵形态约束**（实体下限 + 收盘接近当日最高 + 上影线短），会进一步收紧命中（当前仅 26 只，暂未加）。

### 5B. 回测设计

- 库内已积累 246 个交易日行情（2025-09-09 ~ 2026-09-14）；以 `days_ago` 个交易日前的交易日 t0 为基准
- 行情截断至 t0（`trade_date <= t0`）后复用策略 `select()` 模拟当日选股，保证与实盘逻辑完全一致
- 收益口径：t0 收盘价买入 → 最新交易日收盘价，收益率 %（未计手续费/滑点）
- 输出：胜率、平均/中位收益、最大盈亏、TOP10/BOTTOM5 明细

## 6B. 每日盘后自动化（随机调度模式，v1.2 改造）

- **调度器**：WorkBuddy automation「选股系统-每日盘后随机调度器」，周一至周五 15:30 触发
- **随机化**：调度器生成当天 15:30~18:30 之间的随机时刻（`SystemRandom`，下限保护为当前时间+5分钟），创建一次性 automation「选股系统-盘后执行（日期 时分）」
- **实例自清理**（2026-09-09 起）：实例 prompt 内置收尾自删步骤——执行完毕无论成功/非交易日跳过/失败，均用 automation_update 删除自身（按「选股系统-盘后执行」开头+当天日期匹配），避免已完成的条目残留列表显示"进行中"；调度器每日创建新实例前兜底清理历史同名任务
- **执行内容**：记录执行前 MAX(trade_date) → `run_collect.py --all`（基本面 → 补缺上市日期 → 板块标签 → 东财概念 → 日K增量 → 估值快照 → 衍生指标(v1.4) → 指数 → 资金流 → 当日分时）→ 若 MAX(trade_date) 未变（非交易日）则跳过选股 → 否则 `run_pick.py --all` 遍历全部注册策略（当前 7 个）→ 输出摘要 → 自删实例

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 东方财富接口被网络阻断（已发生） | 数据源切换为新浪；采集层按源隔离，可再切换 |
| 腾讯 fqkline 批量采集触发 IP 级反爬 501（已发生） | 双源熔断：腾讯 WAF → 冷却 600s 走新浪兜底；新浪连续失败 100 次快速失败（单票无第三源，稍后重跑 --quotes） |
| 新浪约 400 次/窗口反爬（已发生） | 采集侧控制并发 + 失败清单；历史回填侧「全局节奏 + 请求预算 + 挑战页即熔断 + 断点续跑」 |
| **东财 push2his / push2 对本机 IP 长期封禁（已发生）** | 资金流历史改用新浪 `MoneyFlow.ssl_qsfx_zjlrqs`（`vip`/`money` 双域名分片并行）；`push2delay` 只能取当天、`datacenter-web` 无此接口，实测已确认；按需求约定全面弃用 push2his |
| 新浪 vs 东财资金流口径不一致（已确认） | 回填默认 `INSERT IGNORE` 只补缺口、不覆盖既有行，避免口径断层 |
| 免费接口频控/限流 | 全局共享节奏 + 重试 + 失败清单；可缩小 limit 分批跑 |
| 系统代理间歇断连（已发生） | 采集会话 trust_env=False 直连 |
| 次新股均线 nan 入库报错（已发生） | 入库前逐值 nan→NULL 清洗 |
| MySQL 5.5 不支持 DATETIME DEFAULT CURRENT_TIMESTAMP（已发生） | 改 TIMESTAMP；etl_update_time 可空 + upsert 显式 NOW() |
| MySQL 5.5 无窗口函数/派生表索引（已发生） | 连涨/量比等滚动口径改为 Python 侧分组计算 + 临时表 UPDATE JOIN；关联子查询改「单独查询 + Python 合并」 |
| MySQL DECIMAL 与 float 混算 TypeError（已发生） | 金额列读出后显式 `float()` 再参与运算 |
| 新浪 getHQNodes 用 https 返回异常内容（已发生） | 改 http 协议 |
| 新浪股票名称含全角空格致按名检索失败（已发生） | 名称检索做空格不敏感匹配（SQL `REPLACE` + 前端去空格） |
| 随机调度时刻早于任务创建完成时间 | 生成时下限保护为当前时间+5分钟 |
